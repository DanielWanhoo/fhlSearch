## 4. 成语检索页布局

- 顶部：三模式切换（分段控件）——「沉浸光感」玻璃底（`glass_bg` + 系统材质 `COMPONENT_ULTRA_THICK` + 1vp `glass_edge` 描边），选中项为主色玻璃胶囊（`glass_primary` + `glass_primary_edge`），与页签栏/玻璃按钮同一套材质语言（见 §5.1）
- 中部：4 个输入格横向排列，按模式限定输入类型
  - **间距必须用「每格自己的左右内边距」实现**，不能用 `Row({ space })`、也不能给格子加 `margin`：带 `layoutWeight(1)` 的子组件，其 `margin` 与 Row 的 `space` **都不参与分宽**，整行会比容器宽出「间距总量」，导致最后一格的右边框落到滚动容器裁剪边界之外（表现为「聚焦的输入框右侧像被挡住 / 缺一条边」）
  - 无声调拼音：字母键盘，自动小写，限 a-z/v
  - 单字声调：数字键盘，限 1~4
  - 单字搜索：单汉字，`maxLength=1`，中文键盘
- 下方：「检索」主按钮 —— **检索开始后，该按钮就地换成「清空所有 / 清空当前 / 二次检索」三键**（`if (hasSearched)` 二选一渲染，不再另设底部固定操作栏）；三键均为「沉浸光感」玻璃按钮（见 §5.1），「二次检索」仅多结果时显示
- 结果区：三分支渲染（唯一 / 列表 + 三键 / 未找到）；结果列表延伸到屏幕底边、从悬浮页签栏玻璃下方穿过
- 结果高亮：被填写过的输入位置，其「字 / 拼音 / 声调」以 `match_highlight`（绿）整行标出；清空按钮（清空所有 / 清空当前）在检索后始终可用
- 宽屏（>600vp，平板横屏）：左栏输入（标题/模式/输入格/提示/检索按钮 → 检索后就地换成三键）+ 右栏结果（滚动列表），中间为**可拖动分隔条**（带圆角滑块手柄，拖动调整左右宽度比例，范围 25%~75%）
- 三个检索页的按钮统一为「沉浸光感」玻璃样式（`components/GlassButton.ets` 全局 @Builder，三页共用）
- 实体键盘：成语 4 个输入格聚焦后可用方向键 ←/→ 移动焦点；诗词 6×5 表格支持 ↑/↓/←/→ 四向移动（`onKeyEvent` + `FocusController.requestFocus`）
- 检索计数：标题右侧显示「检索 N 次」（= 检索栈深 `depth`），每次检索/二次检索 +1，清空当前 -1，清空所有清零
- 快捷键与返回：成语页回车键（Enter）执行检索/二次检索、Esc 键清空当前；诗词页 Esc 键清空表格；系统返回手势同样触发（成语=清空当前、诗词=清空，`onBackPress` 拦截不退出应用）

## 5. 「沉浸光感」悬浮页签栏（HarmonyOS 官方 HDS 组件）

> **结论修正（2026-09-10）**：旧版结论「官方沉浸光感材质需 API 26，本项目 API 24 只能手写等效」有误——那是把 `uiMaterial.ImmersiveMaterial`（API 26）与 HDS `hdsMaterial`（**API 23 起提供**）混为一谈。实测两条真机（Pura 70 / MatePad Pro，均 API 24 / HarmonyOS 6.1.0）`hdsMaterial.getSystemMaterialTypes()` 非空，**系统沉浸光感材质可用**，故已改用官方组件实现。

- **实现方式**：用官方 HDS（UI Design Kit，`@kit.UIDesignKit`）的 `HdsTabs` 替代手写 Dock——页签栏布局、自适应胶囊宽度、图标/文字选中态、按压与切换动效全部由系统按 HDS 规范绘制
- **沉浸光感材质**：`barFloatingStyle.systemMaterialEffect = { materialType: IMMERSIVE, materialLevel: ADAPTIVE }`——玻璃实时折射背后内容，自动跟随系统深浅色、系统材质等级与功耗/温度策略
  - 设备能力由 `common/MaterialUtil.ets` 运行时探测（`hdsMaterial.getSystemMaterialTypes()`，结果缓存）：支持则用 `IMMERSIVE`，不支持则降级为 `ADAPTIVE`（跟随系统材质策略），避免页签栏「发虚 / 消失」
  - `lightColor` 取 `nav_glow`（极淡朱砂红），玻璃据此吐出暖色光泽
- **必须悬浮**：`barOverlap(true)`。实测 `barOverlap(false)` 时页签栏会退化成贴底实心栏（无悬浮胶囊、无光感）
- **离底避让**：`barBottomMargin = bottomInset`（页面加载后读取的真实导航条高度），页签栏浮在手势条之上
- **胶囊宽度**：`barWidth = { mediumWidth: 400, largeWidth: 520 }`——手机段（<440vp）用系统默认宽度（≈65% 屏宽，居中协调），中大屏用固定宽度，避免平板上一颗小胶囊挤在屏幕中间
- **握持手适配**：`adaptToHandedness = isWide`——宽屏跟随握持手左右偏移（单手可达），手机保持居中避免漂移
- **横竖屏统一**：手机竖屏与平板横屏都使用底部悬浮页签栏，内容铺满整屏（`barOverlap(true)`）。曾试过把平板页签栏移到左栏做竖向玻璃导轨（宽度随分栏比例缩放），实测观感不如底部胶囊，已按用户要求回退
- **平板横屏：页签栏水平居中于左栏**（用户要求「由居中改成左栏的中部」）
  - 悬浮页签栏恒居中于 HdsTabs 的**布局盒**，接口没有「水平偏移」参数（`barSideMargin` 是左右对称留白，`adaptToHandedness` 只在跟随握姿时贴一侧），所以只能动「盒」
  - **做法：把布局盒加宽并左移**，取「以左栏中心为中心、且完整覆盖整屏 `[0, W]` 的最小盒」：
    - 盒宽 `L = 2W - 左栏宽`，盒左边缘 `= 左栏宽 - W`（负值，左侧伸出屏幕外）⇒ 盒中心 = 左栏中心，**盒右边缘正好 = W**
    - 内容层两层结构：外层 `width('100%')` 铺满盒（避免被居中偏移），内层固定 `窗口宽` + `translate({ x: W - 左栏宽 })` 从盒左边缘挪回屏幕 `[0, W]`
  - **胶囊宽度 ≤ 左栏宽 - 24**（`wideBarWidth()`，上限 520、下限 200）：页签栏居中于左栏，胶囊比左栏宽就会顶出屏幕左边缘被裁掉
  - 左栏宽 = 分栏比例 ×（窗口宽 - 分隔条 24vp），分隔条宽度常量为 `SplitDivider` 的 `DIVIDER_WIDTH`；分隔条拖动也按同一口径换算，**手指与分隔条 1:1**；比例经 `AppStorage('splitRatio')` 由检索页同步给主页面，**拖动分隔条时页签栏与胶囊宽度实时跟着走**
  - 手机竖屏：左栏宽 = 整屏宽 ⇒ 盒宽 = W、左边缘 0、内容位移 0、胶囊宽度走系统默认，**同一套公式自然退化**，无分支
  - ⚠️ **踩坑**：一开始只把 `HdsTabs` 整体 `translate` 左移、内容再反向平移。看似等价，实则组件布局盒仍在原位 ⇒ 页签栏被屏幕左边缘裁掉、右栏内容被布局盒右边裁掉（「调节分栏比例时页签栏被遮挡 + 右栏显示不完整」）。**必须动布局盒（width + 负 margin），不能只动绘制（translate）**
- **页签栏附近的「沉浸」过渡**：`barFloatingStyle.gradientMask = { maskColor: bar_scrim, maskHeight: 130 }`——内容越靠近页签栏越淡，玻璃胶囊浮在一层柔和底色上（HDS 官方渐变遮罩），不再是「内容被硬切在胶囊边缘」
  - `bar_scrim` 取页面底色的约 70% 透明版（base `#B3F7F1E3` / dark `#B31C1813`），既能把贴近页签栏的内容柔化，又保留「内容在玻璃后面隐约可见」的沉浸感
  - 遮罩高度 130vp（实测渐变从页签栏上方约 145vp 处开始、到页签栏处到达最深）
- **内容从玻璃下方穿过**：`TabContent` 外层**不留白**，检索内容一直铺到屏幕底边、从页签栏玻璃下方穿过（真实内容就是玻璃的折射源，故不再需要手绘「光感」底衬）；页签栏周围不会出现一圈空白遮挡带
- **内容让位（关键）**：留白必须加在**可滚动内容内部**——`Index` 把占位高度（`76 + bottomInset` vp）发布到 `AppStorage('barInset')`，三个检索页用它给滚动内容加底部内边距、把底部按钮抬高，**容器本身不留白**。这样「列表能滚到页签栏上方」且「其余内容从玻璃下方穿过」，不会再出现被空白带截断的半行（踩过的坑：留白加在容器上 = 一条空白遮挡带 + 内容被硬切）
- **滚动收起 / 浮出**：页面 `Scroll` 的 `onScrollFrameBegin` → 页面 `onScrollOffset` 回调 → `HdsTabsController.applyHideAnimation / applyShowAnimation(HdsAnimationMode.SCROLL_ANIMATION)`，下滚收起、上滚浮出（真机实测：上滑浏览列表时页签栏收起、下滑回滚时浮出，方向与应用一致）
- **页签项**：`BottomTabBarStyle` + `SymbolGlyphModifier` 图标（成语 `book` / 诗词 `square_grid_2x2` / 名士 `person_2`），未选中 `text_secondary`、选中 `primary`，随系统深浅色自动取值
- **切换方式**：点页签栏由 HdsTabs 内部驱动（`onChange` 只同步 `currentIndex`）；手机端支持左右滑动切页，平板横屏禁用滑动（避免与分栏分隔条拖动冲突）；横竖屏切换共用同一个 HdsTabs 实例，页面状态保留
- **无障碍**：页签项语义由系统页签栏组件自带（图标 + 文字标签），无需手写

### 5.1 「沉浸光感」玻璃按钮（三个检索页共用）

- **实现**：`components/GlassButton.ets` 导出 `@Component GlassButton`（`@Prop label/primary/desc` + `action` 回调；用组件而非全局 `@Builder` 是为了在内部维护按压状态、驱动动画），成语/诗词/名士三页共用同一套按钮样式，调用点写 `GlassButton({ label: '检索', primary: true, desc: '...', action: () => {...} })`
- **材质**：`.backgroundBlurStyle(BlurStyle.COMPONENT_ULTRA_THICK, { colorMode: ThemeColorMode.SYSTEM, adaptiveColor: AdaptiveColor.AVERAGE })`——与悬浮页签栏同一套系统材质语言，透出并实时模糊背后内容，跟随系统深浅色与材质策略
- **构成（光感均匀分布）**：通体等厚的半透明底（`glass_bg` 中性 / `glass_primary` 主色）+ **整圈 1vp 发丝描边**（`glass_edge` / `glass_primary_edge`，四边等宽等亮）+ 四周均匀的柔和外发光（`nav_glow` / `card_shadow`，`offsetY` 仅 2）
  - **不做半截高度的高光色带**：旧版用一层 55% 高的高光渐变叠在按钮上，会出现「上亮下暗」的断层，光感分布不均——已按用户反馈重写为通体等厚 + 均匀描边
- **尺寸**：高 42、圆角 21（胶囊）、`layoutWeight(1)` 由 Row 均分槽位；需要限宽时（诗词页 `清空/开始检索` 限 200vp）由调用方套一层带 `constraintSize` 的 Row
- **按压反馈（有节奏的动效，不生硬）**：组件内部维护按压状态并驱动动画
  - **震动反馈**：按下的瞬间先触发一次轻触震动（`common/Haptics.ets` 的 `Haptics.tick()`——系统预置触感 `haptic.effect.soft`、强度 70、`usage=touch`），触觉先于视觉、按压更「实」；设备能力**只在首次按压时探测一次并缓存**：先查本机有无振动器（`getVibratorInfoSync()`），没有则直接跳过、不发任何无效调用；有振动器再查是否支持该预置触感，不支持才退化为 12ms 定长轻震。**无振动马达的设备（如 MatePad Pro）因此完全静默**；60ms 内的重复触发只算一次（连点不堆积）
  - 按下：120ms（`Curve.FastOutSlowIn`）收缩到 0.94，同时内层高光层淡入（`glass_press`）、投影收紧（radius 10→6、offsetY 2→1），形成「压进玻璃」的手感
  - 抬起：`curves.springMotion(0.34, 0.66)` 弹簧曲线回弹（略微过冲后归位），高光柔和淡出
  - 高光层与按钮同形同圆角、整块均匀提亮，不产生局部亮斑
- **圆形小尺寸变体**：名士详情弹窗右上角的关闭键 —— 同样「通体等厚半透明底 + 系统材质模糊 + 整圈 1vp 描边」，只是尺寸 32×32、圆角 16（正圆），按下同样触发 `Haptics.tick()`。
  - ⚠️ 它落在**卡片**（`card_bg`）上，不能用页面上的 `glass_bg` / `glass_edge`：浅色主题下卡片几乎是白的，白玻璃叠白卡片 = **完全看不见**。必须用 `glass_card_bg` / `glass_card_edge`（浅色主题取暖墨半透明，比卡片暗；深色主题仍是白色半透明）
- **无障碍**：内置 `accessibilityText`（按钮文字）+ `accessibilityDescription`（调用方传入的用途描述）

### 5.2 同套材质的「沉浸光感」分段控件（成语页模式切换）

- **位置**：成语检索页顶部的「拼音 / 声调 / 单字」三模式切换
- **材质**：整条是一块玻璃（`.backgroundColor(glass_bg)` + `.backgroundBlurStyle(COMPONENT_ULTRA_THICK, { colorMode: SYSTEM, adaptiveColor: AVERAGE })` + 整圈 1vp `glass_edge` 描边），与页签栏、玻璃按钮同一套系统材质与描边语言
- **选中项**：主色玻璃胶囊（`glass_primary` + `glass_primary_edge`），切换时背景/描边 180ms `FastOutSlowIn` 过渡（只动颜色，无位移残影）
- 取值方式与玻璃按钮一致：颜色全部来自 base/dark 成对资源，深浅色自动切换

| 名士检索 | 检索后三键：「清空所有」「清空当前」「二次检索」 |

## 6. 沉浸式

- **窗口级全屏**：`EntryAbility` 调用 `setWindowLayoutFullScreen(true)`，让整个窗口布局铺满整屏（含状态栏/导航条），页面「背景 + 内容」一起延伸到边缘；同时状态栏/导航条透明（`#00FFFFFF`）+ 暖色窗口背景（`setWindowBackgroundColor`）。这是「整应用沉浸」的官方做法，也能消灭底部白条（非全屏布局会自动避让底部 AI 横条）
- 系统栏图标颜色随深色模式自动切换（`text_primary`），保证可读
- **不用** `expandSafeArea` / `ignoreLayoutSafeArea`（那是「单页面沉浸」的另一套方案，与窗口全屏混用会打架、导致内容不贴边或露白条）
- `Index` 页在 `aboutToAppear`（此时窗口已就绪）用 `window.getLastWindow(getContext(this))` 读取状态栏/导航条真实高度（px → vp），存入 `AppStorage`（`topInset` / `bottomInset`）；顶部状态栏用 `TYPE_SYSTEM`，底部手势条用 `TYPE_NAVIGATION_INDICATOR`。注意：`onWindowStageCreate` 阶段窗口未就绪，`getWindowAvoidArea` 会返回 0，故不能在 EntryAbility 里读
- 底部悬浮页签栏离底：`barBottomMargin = bottomInset`，`bottomInset` 只取手势条高度（`TYPE_NAVIGATION_INDICATOR`）
- 标题顶部内边距用 `topInset`、标签栏底部用 `bottomInset`，避让系统图标与手势条
- 内容让位：Index 把占位高度发布到 `AppStorage('barInset')`，由三个检索页在**滚动内容内部**留白（列表可滚到页签栏上方，其余内容从玻璃下方穿过）；宽屏左栏、空状态提示各自用 `barInset` 抬高（名士页原底部固定操作栏已取消，三键移到页面上方），长内容区（宽屏右栏）容器不留底部内边距

## 7. 动效

| 场景 | 动效 | 时长 |
|------|------|------|
| 标签页切换 | HdsTabs `animationDuration` 平滑过渡 | 300ms |
| 页签栏滚动收起/浮出 | 下滚收起、上滚浮出（HDS `SCROLL_ANIMATION` 系统动画） | 系统时长 |

| 模式切换 | 选中项背景色过渡 | 150ms ease-out |

| 结果出现（成语/诗词列表） | 错峰淡入上滑，每张延迟 45ms 依次入场 | 250ms ease-out |

## 8. 多端适配

- 断点 600vp
- 手机（窄屏）：单列，内容撑满
- 平板（宽屏）：成语页左输入右结果双栏；诗词页左表格右结果双栏；输入格与结果加宽；双栏中间为可拖动分隔条（带滑块手柄），拖动调整左右比例（25%~75%）
- 手机竖屏：底部居中悬浮页签栏（HDS 按宽度断点自适应胶囊宽度 ≈65% 屏宽）
- 平板横屏：与手机一致使用**底部悬浮页签栏**（HDS 按宽度断点自适应胶囊宽度），双栏内容铺满整屏；页签栏**水平居中于左栏**（随分隔条拖动实时移动，见 §5）
- 平板横屏的页签栏**常驻**：不随任一侧栏滚动而起收/浮出（手机竖屏仍保留「下滚收起、上滚浮出」）。理由：平板页签栏居中在左栏，随右栏结果列表滚动而消失会让人找不到导航；竖屏切到横屏时会主动把已收起的页签栏浮出来
- 平板横屏的**左栏可上下滚动**：窗口变矮（自由窗口/分屏）时左栏内容不会被页签栏挡住，可滑动看全
  - 左栏内容**靠上对齐**（与窄屏一致）：`Scroll` 会把「比视口小的子组件」**垂直居中**，所以内层 Column 加 `.constraintSize({ minHeight: '100%' })` 铺满视口 —— 内容足一屏时靠上、超过一屏时自然变成可滚动（踩坑：一开始给内层加 `justifyContent(Center)` 想保持居中，结果三页左栏全被 Scroll 居中，已去掉）
  - 三页（成语/诗词/名士）一致
  - **页签栏避让留白放在滚动内容内部**（`.padding({ bottom: barInset + 24 })` 加在内层 Column 上），容器本身**不留**底部内边距 —— 否则页签栏附近会出现一条「空白带」把内容截断（与手机竖屏踩过的坑同源）；这样滚动时内容能从页签栏玻璃下方穿过，滚到底最后一行恰好停在页签栏上方
- 页签栏尺寸：由 HDS 规范给出（胶囊圆角、条目高度、图标与文字字号均为系统值），宽度按断点取 `barWidth`（手机默认 / 平板 400~520vp）

### 10.3 检索流程与结果三态

- 数据源：`众里寻他.xlsx`（115 位名士），脚本 `scripts/excel_to_mingzi.py` 生成 `data/mingzi_db.ets`
- 规范化：爱好「奕棋」→「弈棋」；朝代「五代十国（南唐）」→「五代十国」
- **填写与检索分离**（2026-10-16 改版）：条件行选/填后只**记录条件**（行内绿色显示），不触发检索；由用户点「检索 / 二次检索」时才执行
- **首次检索**：初始状态（未检索）时，条件区上方显示大「**检索**」键，点它按**当前已填写的全部条件**（按页面从上到下的模式顺序）依次叠加检索；检索开始后该键**自动隐藏**，由三键接手；点「清空所有」回到初始状态时它重新出现
- **二次检索**：继续在条件行里填/改条件 → 点「二次检索」，把**新填写（或与已应用值不同）**的条件叠加到上一次结果之上；已生效的条件保持不动
  - **同一模式改选 = 替换该条件**（例：把「朝代：先秦」改成「朝代：汉」），不会与旧值求交集
  - 没填新条件就点「二次检索」→ 弹提示「请先填写新的检索条件」，不会重复检索；没填任何条件就点「检索」→ 弹「请先填写检索条件」
- **实现**：按条件集合**重建检索**（`service.reset()` 后依次叠加），条件始终按页面从上到下的模式顺序排列，结果可复现；「清空当前 / 返回上一级」仍然是弹出一层条件
- 结果三态：
  - **唯一**：展示「完成检索」+「名士（朝代）」卡片 +「清空所有」「二次检索」键
  - **多结果**：全部以「名士（朝代）」列出 +「清空所有」「清空当前」「二次检索」三键
  - **无结果**：提示「未检索到该名士」+「清空所有」「二次检索」键（可改条件后二次检索）
- **按钮位置：页面上方**（检索条件之上 / 之下、结果列表之前）——窄屏固定在大标题/「已检索」面包屑下方，宽屏「检索」键在左栏条件区上方、三键在右栏顶部；原「底部固定操作栏」已取消（不再贴着底部手势条、也不占用结果区滚动空间）
  - 「清空当前」仅在**有上一层可回退**（已应用条件 ≥ 2）时显示；「二次检索」**恒显示**（它是「让新填条件生效」的唯一入口，结果 0 条或 1 条时同样需要）
- 检索次数计数 = **当前叠加的条件层数**（与「已检索」面包屑条数一致）：清空所有清零，返回上一级 -1
- 结果卡片错峰淡入上滑（45ms 间隔），唯一结果弹入
- **详情弹窗**：点击结果卡片弹出居中详情弹窗（CustomDialog），展示全部字段；已应用检索关键词以绿色加粗高亮；「其他描述」每条另起一行并标注表格列号（描述1~15，跳过空列）
  - **关闭键**：右上角「×」包在 **32vp 圆形「沉浸光感」玻璃底**里（底 + 系统材质 `COMPONENT_ULTRA_THICK` 模糊 + 整圈 1vp 发丝描边，圆角 16 = 正圆）。底色/描边用 **`glass_card_bg` / `glass_card_edge`**：弹窗底色是**卡片**，浅色主题下卡片接近白色，用页面上的 `glass_bg`（白 65%）会「隐形」—— 故浅色主题取暖墨半透明（比卡片暗），深色主题仍是白色半透明，与页签栏/玻璃按钮同一套材质语言；按下同样触发一次轻触震动（`Haptics.tick()`）。旧版是一个裸的 `SymbolGlyph`，在卡片底色上缺少「可点」的边界感

### 10.5 菜单模式选项：文本滑动选择器弹窗

- **实现**：官方 `this.getUIContext().showTextPickerDialog(...)`（`TextPickerDialogOptions`，API 8 起提供，本项目 API 24 真机实测正常），取代初版的「居中 CustomDialog + 选项列表」
- **参数**：
  - `range` = 当前模式的选项数组（朝代/爱好/社团/品阶）；`selected` 默认停在「该模式当前已选的选项」上（未选过则第 0 项）
  - `defaultPickerItemHeight: 40`、`canLoop: true`（滚轮循环，短列表如品阶「天/地/玄」也能顺滑换选）
  - 文字三态样式：选中 `primary` 20fp Medium、普通 `text_primary` 17fp、两侧渐隐 `text_secondary` 15fp；按钮 `确定` 主色、`取消` 辅助色；对话框底色 `card_bg`
  - 全部取 base/dark 成对颜色资源，随系统深浅色切换
- **交互**：只有点「确定」才执行检索（`onAccept`），**单纯滑动不触发**，避免滑过就搜的误触；`onCancel` 不做任何事
- **震动反馈**：滚动滚轮每滑过一项轻震一次（系统「刻度感」），由 `enableHapticFeedback: true` 开启。注意此能力**受权限门控**：该项默认值本就是 `true`，但必须先在 `entry/src/main/module.json5` 声明 `ohos.permission.VIBRATE`（普通级 · system_grant，装包即授权、无需运行时申请），否则开关等于空转、滚轮完全静音。实测触感为系统原始效果 `haptic.slide`（12ms / 强度 50 / usage=touch）；震动由系统 Picker 组件在应用进程内直接触发，无需自己调用 `vibrator`。设备差异：MatePad Pro（本机）**无振动马达**，同版本只发出触感请求、物理上不震（`No local vibrator capacity information found`），属硬件能力问题
- **无障碍**：模式行描述改为「点击弹出滑动选择器，上下滑动选择选项」
- 说明：初版曾尝试 `bindMenu` / `CustomPopupController`，前者无法自定义滚动回弹、后者 API 24 不存在，才退到居中 CustomDialog；本轮改为系统选择器弹窗后，视觉与手感都回归 HarmonyOS 原生范式（滚轮 + 惯性 + 选中放大回弹）
