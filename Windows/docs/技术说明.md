# 忘川检索 fhlSearch · 技术说明

面向维护者。记录架构决策、编码约定、以及**为什么这么做**。

---

## 一、技术选型

| 项目 | 选择 | 理由 |
| --- | --- | --- |
| 语言 / 框架 | C# + WinForms | Win32 原生控件，Win7→Win11 表现一致；开发效率高 |
| 目标框架 | **.NET Framework 4.0**（`net40`） | 4.x 是就地升级，编到 4.0 就能在 4.0/4.5/4.8 上跑；Win10/11 自带，Win7 覆盖率高 |
| 运行时依赖 | **零第三方库** | 只用 `System` / `System.Drawing` / `System.Windows.Forms` / `System.Core`；不需要 Office、不需要任何 NuGet 运行时包 |
| 编译 | .NET SDK 8 交叉编译 net40 | 参考程序集由 `Microsoft.NETFramework.ReferenceAssemblies` NuGet 包在**编译期**提供，不进产物 |
| 题库 | 编译期内嵌 | 运行时零文件依赖，单 exe 拷走即用 |
| 位数 | `AnyCPU` + `Prefer32Bit=false` | 同一 exe 在 32/64 位系统上都是原生运行 |

**为什么不用 .NET 5/6/8？** .NET 5+ 最低要求 Windows 10 1607，不满足「最低 Win7」这条硬约束。.NET Core 3.1 是最后一个支持 Win7 的，但生态与生命周期都不合适。

## 二、数据管道

```
data/*.xlsx
        │  tools/build_data.py  (openpyxl，编译期执行一次)
        ▼
src/FhlSearch/Resources/bank.txt   ← UTF-8，紧凑文本，55 KB
        │  csproj: <EmbeddedResource LogicalName="FhlSearch.bank.txt">
        ▼
忘川检索.exe                        ← 运行时 Assembly.GetManifestResourceStream 读取
```

**bank.txt 格式**（自定义，零解析依赖）：

```
FHLS-BANK 1
# 注释行
[OPT_DYNASTY]        每个选项一行
[OPT_HOBBY]
[OPT_CLUB]
[OPT_RANK]
[IDIOM]              成语\t拼音①②③④\t声调①②③④
[POEM]               诗句\t诗词名\t作者
[PERSON]             名士\t朝代\t品阶\t职业\t生逢\t出身\t技能\t爱好(\x1f)\t社团(\x1f)\t描述(\x1f)
```

- 字段分隔 `\t`，记录分隔 `\n`，多值分隔 `\x1f`（Unit Separator，题库里不会出现这个字符）
- 选择这套格式而不是 JSON/XML：解析就是 `Split`，**零依赖、零反射、启动瞬间完成**

**几个刻意的处理**：

1. **成语的「单字」列从成语现算**，不读题库里的 J–M 列。
   那几列是 `=MID(A行号,n,1)` 公式，openpyxl 重写文件会丢掉公式缓存值，靠它不可靠。
2. **拼音统一转小写**。题库表头写的是「无声调小写」，实际有 2 条大写（`Shuang` / `Zhi`），归一化后显示和匹配都一致。
3. **朝代保留原始值**，另存一个去括号的归并值用于匹配。
   题库里是「五代十国（南唐）」，菜单选项是「五代十国」，靠 `StripParen` 归一。
   *注意：如果对「唐」做包含匹配会误伤「五代十国（南唐）」，所以朝代用**精确匹配**而不是模糊匹配。*
4. **名士表按「名称所在行为块首」归并**合并单元格，把多行拆出来的爱好/社团/描述合并成数组。

## 三、检索算法

### 成语

- 拼音：`Py[pos].IndexOf(value, OrdinalIgnoreCase) >= 0` —— **子串**匹配，所以声母、韵母、完整拼音都能命中
- 声调：解析成 `int` 后精确比较（题库里声调是数字类型）
- 单字：精确比较
- 空输入 = 该位不限
- 层级检索：用一个 `List<Level>` 栈，每层的筛选范围是上一层的结果集

### 诗词（择字成诗）

给定 30 格（空格为 `'\0'`），找出所有能拼出的诗句：

1. 统计字格里每个字的可用格子数 `avail[c]`，并记下每个字所在的格子下标 `where[c]`
2. 对每条诗句，统计每个字的需求数 `need[c]`；只要存在 `need[c] > avail[c]` 就淘汰
3. 通过后按顺序分配具体格子：同字依次取 `where[c][n]`，天然保证**同一条诗句不会重复占用同一格**
4. 「重复字的诗句」需要字格里有对应数量的相同字，上面这套流程自动满足

复杂度 O(诗句数 × 5)，282 条数据量下是瞬时的。

### 名士

- 菜单模式（朝代/爱好/社团/品阶）：**精确匹配**（朝代先 `StripParen` 归一）
- 文本模式（职业/生逢/出身/技能/其他描述）：**模糊匹配**
  - 归一化：`Cjk(text)` 只保留汉字（`0x4E00–0x9FFF` 与 `0x3400–0x4DBF`），去掉标点、数字、字母、空格、换行、括号
  - 匹配：归一化后的**连续子串**包含关系 —— 不拆分检索词
  - 归一化结果在**载入时算好缓存**在 `Person` 上（`JobN` / `MeetN` / `OriginN` / `SkillN` / `DescsN`），检索时不再重复处理
- 「其他描述」只在 `描述1–15` 里查，不含技能/职业/生逢/出身（按需求决策 #7）

## 四、界面架构

界面在 2026-10-15 整体重构过（v1.1），**与安卓版《忘川检索》共用同一套设计规范**：
配色/字号/间距/圆角全部取自安卓版的 `res/values/colors.xml`、`dimens.xml`，
dp 与逻辑像素 1:1 对应，再由 `Ui.Scale` 统一做 DPI 缩放。

### 几个关键实现决定

**1. 弹窗一律是标准 Windows 对话框。**

`FormBorderStyle.FixedDialog` + 标题栏 + 关闭按钮，`ShowDialog(owner)` 做真模态，
`StartPosition.CenterParent` 居中于主窗口，不进任务栏，Esc 关闭。
里面用原生 WinForms 控件（`ListBox` / `TextBox` / `Button`），只把底色换成 `Pal.CardSoft`，
所以既像 Windows 对话框，又和主界面同源。

早期版本用的是"半透明遮罩 + 屏幕正中卡片 + 点卡片外面关闭"的移动端做法，已废弃：
那不是桌面软件的交互习惯（盖住整个主界面、没法拖动、没有标题栏、关闭方式不标准）。

**对话框字体必须自己按 DPI 缩放。**
一开始对话框用的是 `SystemFonts.MessageBoxFont`，它是**像素单位**的字体（lfMessageFont 给的是像素高），
不会随 DPI 放大 —— 在 200% 缩放的机器上字只有应有大小的一半，小到看不清。
现在统一走 `Fonts.Of(14, false)`（dp 单位、`Ui.Pf` 换算，14dp ≈ Windows 对话框的 10.5pt），
和主界面同一套字体缓存。

**自定义控件不设手型光标。**
`Cursor = Cursors.Hand` 在 200% 缩放下会显示成一个明显偏小的手型（系统那个手型光标位图
没有跟着 DPI 放大），鼠标移到按钮和左侧导航上时会"突然变小"。
标准 Windows 按钮本来就是箭头光标，所以直接去掉了所有 `Cursors.Hand`：
既修掉了这个毛病，也更符合桌面软件的习惯。`ResultList` 等可点区域靠悬停变色给反馈。

**2. 宣纸渐变必须"全局对齐"。**
`MainForm.OnPaintBackground` 用 `ClientRectangle`（而不是 `e.ClipRectangle`）画渐变，
子控件要背景时调 `Paper.Paint(this, g)` —— 它把控件坐标换算回窗体坐标再画同一张渐变。
否则每个子控件都会从自己的顶边重新开始渐变，出现一条条色阶。

**3. 圆角外面的底色必须靠 `ISurface` 自动继承 —— 这是踩过的一个大坑。**

控件画圆角矩形时，四角会露出"它背后的底色"。这个底色**不能**一律当成宣纸：

- 控件坐在纸面上 → 画宣纸渐变（`Paper.Paint`）
- 控件坐在卡片上 → 必须画**卡片色**

一开始我在每个控件里直接写 `Paper.Paint(this, g)`，于是卡片里的选项卡、输入框、
（对话框里的）按钮四角都露出一个**方块状的纸色残余**，非常显眼。

现在改成：

- `inKControl.PaintBg(g)` 统一决定底色：`Behind`（显式指定）→ 沿父链找 `ISurface` → 宣纸渐变
- `CardPanel` / `PoemGrid` / 对话框实现了 `ISurface`，卡里的控件自动拿到卡片色
- **任何自绘控件的 `OnPaint` 里都不许再直接调 `Paper.Paint`**，一律用 `PaintBg(g)`

**4. 为什么用「自绘控件 + 内嵌真实 TextBox」。**
中文输入必须要输入法（IME），而 IME 只能作用于真实的可编辑控件。所以涉及**中文输入**的地方
（诗词字格、名士文本检索）都用「自绘外观 + 内嵌无边框 TextBox」的混合方案；
纯展示的部分（按钮、选项卡、列表、卡片、条件行）则完全自绘。

**5. 占位符要写进真实 TextBox，不能画在它背后。**
`TextBox` 是不透明子窗口，画在父控件里的居中占位符会被它整个盖住（只剩两条边露出来）。
所以 `FInput` 的占位符是"没聚焦且没内容时把提示文字写进 TextBox 并改成灰色"，
聚焦或有内容时清掉。只在未聚焦状态出现，所以不会和输入法打架。

**6. 侧栏导航图标直接复用安卓版的 vector pathData。**
`Theme/Painting.cs` 里带一个极简 SVG path 解析器（M/L/H/V/C/S/Q/T/Z 及相对形式），
把安卓 `ic_fhl_book.xml` / `ic_fhl_grid.xml` / `ic_fhl_person.xml` 的路径原样搬过来，
两边图形完全一致，也不用自己手画贝塞尔。

**7. 「检索」/「二次检索」是同一个按钮位上的两个状态。**
成语与名士模块的左栏底部「检索」、结果区「二次检索」不是两个独立按钮，而是**一对**：
`UpdateButtons(n)` 是唯一的开关处，`n` = 右栏当前结果条数，`n < 0` 表示还没检索过。

| `n` | 左栏「检索」 | 结果区「二次检索」 | 清空所有 / 清空当前 |
| --- | --- | --- | --- |
| `< 0`（初始态） | 显示 | 隐藏 | 隐藏 |
| `0`（没筛出结果） | 显示 | 隐藏 | 显示 |
| `≥ 1` | 隐藏 | 显示 | 显示 |

- 回到初始态（`清空所有`，或 `清空当前` 把层级栈弹空）时 `UpdateButtons(-1)` 自动把「检索」还回来；
- **`n == 0` 特意让「检索」留着**：条件写错了要能直接重搜，否则只能先「清空所有」，
  等于把用户填的条件也一起抹掉（自找的"死路"）；
- 「二次检索」隐藏时，结果区那行改由「清空所有 / 清空当前」两个键平铺，不留半截空位；
- 名士模块的左栏条件列表会按 `_btnSearch.Visible` 决定要不要给按钮留高度，按钮收起时列表自动补满；
- `FButton.OnVisibleChanged` 会清掉 `_hover` / `_down`：鼠标正停在按钮上时按钮被藏起来，
  `WM_MOUSELEAVE` 未必送到，不清的话它下次出现会"自带高亮"。

### DPI 缩放

`app.manifest` 声明 `dpiAware=true`，程序内部按 `Ui.Scale = 屏幕DPI / 96` 自行缩放。

- **所有像素常量都过 `Ui.Px()`**，字号用 `GraphicsUnit.Pixel`（dp 直接当逻辑像素用）
- 实测环境是 200% 缩放，`Ui.Scale = 2`，一切正常
- 初始窗口大小会**按屏幕工作区收缩**，避免在小屏（如 1366×768 @150%）上超出屏幕
- 字体做了回退链：微软雅黑 UI → 微软雅黑 → 黑体 → 宋体 → Arial，英文版 Windows 上也不会出方块

### 图标

`tools/make_icon.py` 生成**朱砂方印**（圆角正方形 + 描金双框 + 竖排「忘川」楷体），
与安卓版图标（朱砂圆印）同一套美术：同一组色值 `#9E2B25→#C0392B` / `#B08A3E` / `#F7F1E3`，
只有外形不同（桌面图标用圆角正方形更常见）。每个尺寸都按 4 倍超采样单独绘制，
16/24/32 px 下笔画依然清晰。

## 五、编码约定（都是踩过的坑）

| 文件类型 | 编码 | 原因 |
| --- | --- | --- |
| `.cs` | UTF-8（无 BOM 也可） | Roslyn 严格按 UTF-8 解码，实测无 BOM 也正确 |
| `.ps1` | **UTF-8 with BOM** | Windows PowerShell 5.1 无 BOM 时按 ANSI(GBK) 解码，中文注释会**破坏语法** |
| `.bat` | **GBK / cp936** | cmd.exe 按系统 OEM 代码页读取批处理 |
| `.txt`（面向用户） | **UTF-8 with BOM** | Win7 记事本无 BOM 时当 ANSI 解，中文乱码 |
| Python 脚本 stdout | 跟随系统编码 | 强制 UTF-8 会让 cmd 控制台（GBK）显示乱码 |

`tools/bom.py <文件...>` 可给 `.ps1` 补 BOM。

**另一条**：本机 `Encoding.Default` 是 **gb2312**，所以程序里读文件必须**显式指定 UTF-8**
（`new StreamReader(s, new UTF8Encoding(false), true)`），不能用 `Encoding.Default`。

> 结果逐条相同，才能确认没有回归。整字精确拼音那几条就是为「狗急跳墙」的拼音订正加的。

## 七、已知取舍

1. **Win7 需要 .NET Framework 4.0+**。这是为了开发效率做的取舍；
   如果将来确实需要「零依赖」的 Win7 支持，可以再补一个原生 C++/Win32 版本，界面视觉可保持一致。
2. **诗词字格「填完一个字自动跳下一格」**是自己加的便利功能（需求没写）。
   只在新填空格子时触发，修改已有格子不会跳。
3. **输入法激活时 TextBox 的 KeyCode 会变成 `Keys.ProcessKey`(229)**，
   所以回车/Esc 走 `ProcessCmdKey` 而不是 `KeyDown`；同时拼音/声调输入框设了
   `ImeMode.Disable`，从根源上避免被输入法抢按键。
4. **`Fonts.Of()` 返回的是缓存中的共享 Font 实例，绝对不能 `using` 包起来 Dispose**。
   项目里曾有 11 处这么写，导致后续绘制抛 `ArgumentException(参数无效)`，已用
   `tools/oneoff/fix_font_dispose.py` 全部修正。
5. **`Control.SetBounds()` 不要用在"应该保持隐藏"的控件上**（名士模块底部的「检索」键会随状态显隐）。
   显隐只由 `Visible` 决定，不要顺带调 `SetBounds`。
6. **`ResultList` 的行高回调会被频繁调用**（每次重绘都会遍历所有行算总高度），
   所以行高要缓存成一个字段，不要在回调里现算或 `new Graphics`。
