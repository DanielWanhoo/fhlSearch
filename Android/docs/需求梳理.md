## 一、需求原文的三份文件（逐条转写）

| 来源文件 | 模块 | 大标题 |
| --- | --- | --- |
| `成语检索.txt` | 成语检索 | 山石雅集第 14 题 |
| `诗词检索.txt` | 诗词检索 | 山石雅集第 15 题 |
| `名士检索.txt` | 名士检索 | 众里寻他（原写"千里寻她"，2026-10-15 改定） |

### 1.1 成语检索（原文要点）

1. 三种检索模式：**拼音 / 声调 / 单字**；每种模式都有**四个输入框**，对应成语的第 1–4 个字。
2. 拼音模式：输入英文字母（完整拼音或单个声母/韵母，**模糊检索**），出现其他符号 → "非法字符"提示。
3. 声调模式：输入阿拉伯数字，其他符号 → "非法字符"提示。
4. 单字模式：输入单个汉字，其他符号 → "非法字符"提示。
5. 点"检索"后在题库中检索，展示**全部结果（成语 + 拼音 + 声调）**。
6. 结果下方按键：**清空所有检索 / 清空当前检索 / 二次检索**。
   - 二次检索：切换其他模式、填新内容，在**上一次的结果**范围内再筛。
   - 清空所有检索：回到初始状态。
   - 清空当前检索：只清当前层结果，返回上一级检索。
7. 结果里要把**用户当前填了内容的那几位**的汉字、拼音、声调都**标绿**。
8. 结果仅 1 条 → 只给"清空所有检索 / 清空当前检索"。
9. 无结果 → 提示"未检索到对应结果"，给"清空所有检索 / 清空当前检索"。
10. 题库：`成语检索.xlsx`。

### 1.2 诗词检索（原文要点）

1. 初始界面是**长 6 宽 5 的表格**（已按你 Windows 版确认：**6 列 × 5 行 = 30 格**），表格下方**常驻**"清空"与"检索"键。
2. 每格填 1 个汉字；非汉字 → "非法字符"；输入 2 个以上汉字 → **只取第一个**。
3. 可用**方向键**选格，选中格用**红色方框**标亮。
4. 点检索后，程序从格子里选出 **5 个汉字**，按合适顺序排序，与题库某条诗句匹配，用**绿色方框**分别标亮这些汉字。
5. 下方给出查找结果，并附上**题目（诗词名）和作者**。诗句**不必按格内原顺序**呈现（顺序无关）。
6. 题库：原文写 `名士检索.xlsx`，**实际应为 `诗词检索.xlsx`**。

### 1.3 名士检索（原文要点）

1. 9 种检索模式：**朝代 / 爱好 / 社团 / 品阶 / 职业 / 生逢（生于…）/ 出身-身世 / 技能 / 其他描述**。
2. 选项型（菜单选项卡）：朝代 15 项、爱好 10 项、社团 9 项、品阶 3 项，具体项与需求原文一致。
3. 其余 5 种为**输入框 + 模糊检索**（不拆分检索词，忽略标点/空格等非汉字字符）。
4. 结果 1 条 → 以"**名士（朝代）**"展示，下方只给"清空所有检索"。
5. 结果 ≥2 条 → 全部列出，给"清空所有检索 / 返回上一级检索 / 二次检索"。
6. 增加**检索次数计数**（清空所有检索时清零）。
7. 无结果 → 提示"未检索到该名士"，给"清空所有检索"。
8. 二次检索切换模式时，**必须保留原有检索结果**。
9. UI 上检索模式以**列表形式**呈现；朝代/爱好/社团/品阶用**菜单式选项卡**。
10. 题库：`名士检索.xlsx`。

## 四、三大模块的 Android 行为细节

### 4.1 成语检索

- 顶部：大标题"**山石雅集第 14 题**"＋右上角"检索次数：N"。
- 副标题："按拼音 / 声调 / 单字检索成语"。
- 模式切换：三段式选项卡（拼音 / 声调 / 单字）。
- 四个输入框（横排，手机上也保持一排四格，与截图一致）。
- 拼音：连续子串模糊匹配，大小写不敏感；声调：1–4 精确；单字：精确相等；**空格子 = 该位不限**。
- 非法字符：输入框变红 + 提示"非法字符"，不执行检索。
- 绿色标注：填了内容的位次，在**汉字 / 拼音 / 声调**三处同时标绿。
- 层级检索（与 Windows 版一致）：
  - 第 0 层在全部 319 条里筛；已有结果时在上一层结果里筛。
  - "二次检索"= 清空当前模式输入框 + 显示提示条"二次检索中 · 当前范围：N 条"。
  - "清空当前检索"退回上一层；"清空所有检索"回初始态。
- 结果 ≥2 条时按第 1 字拼音升序排列。

### 4.2 诗词检索

**字格规格**：**6 列 × 5 行 = 30 格**，每格 1 个汉字；格下常驻"清空""检索"（截图为"清空 / 开始检索"）。

**填字与选格（按你确认的交互方式）**

| 操作 | 行为 |
| --- | --- |
| 点某个格子 | 该格获得红色方框并自动**弹出汉字输入法**，直接打字即可 |
| 输入多个汉字 | **只保留第一个汉字** |
| 输入非汉字（字母/数字/标点） | 该格变红 + 提示"**非法字符**" |
| 格子已有字 | 点进去可直接改；输入法退格删空＝清空该格 |
| **接外接物理键盘时** | 启用 ↑ ↓ ← → **移动选中格**（红框与光标一起跟随）；`Tab`/`Shift+Tab` 前后移动；`Backspace` 清空当前格；键盘直接打字填入当前格<br>（v1.4 起**界面上不再有虚拟方向键面板**，方向键只由物理键盘触发） |
| 未接物理键盘时 | 纯手指点选 + 输入法，界面保持干净 |

**匹配算法（顺序无关）**

1. 收集 30 格中所有已填汉字，并记录每个汉字出现在哪些格子。
2. 遍历 282 条诗句，判断它的 5 个字能否**各占用一个不同的格子**凑齐（诗句本身含重复字时，格内也必须有两个相同的字）。
3. 与格内排列顺序**无关**——即需求原文的"最终的诗词句不一定在表格中按照原顺序呈现"。
4. 命中后在用到的格子上标 **①②③④⑤**，一眼看出答案由哪几格拼成。

**结果展示**：列出全部命中诗句，格式 `诗句 · 《诗词名》 · 作者`；点某条 → 字格上**绿框高亮**对应的 5 格并显示序号；默认自动选中第一条。无命中 → 提示"**未找到可组成的诗句**"。

**绿色方框**：只高亮"当前选中那条"所用的 5 格；改选另一条时高亮随之切换（不会多条混在一起看不清）。

### 4.3 名士检索

- 9 个模式竖排**列表**；朝代/爱好/社团/品阶 点开后是**菜单式选项卡**（可再次点击取消）。
- 5 个文本模式做**归一化模糊匹配**：检索词与候选文本都去掉所有非汉字字符后，做连续子串匹配。
- 结果格式 `名士（朝代）`；检索次数计数；层级检索逻辑与成语模块一致（按钮名按需求用"**返回上一级检索**"）。
- 数据兼容处理（沿用 Windows 版已确认的方案）：题库"五代十国（南唐）"按包含匹配命中"五代十国"；"辽"无数据点了提示未检索到；大乔无品阶；"（误导）"干扰项照常参与检索。

## 十四、第四轮：诗词字格"选中框与输入焦点不同步"修复（2026-10-15）

> 用户报障：**平板上用物理键盘方向键时，只有标亮的边框受控，光标没反应。**

### 14.1 实测复现（uiautomator 节点属性对照，修前）

用 `selected="true"`（哪个格子画着朱砂框）与 `focused="true"`（哪个格子的隐藏 EditText 拿到输入焦点）两个属性对照：

| 操作 | 选中框 | 输入焦点 | 同步 |
| --- | --- | --- | --- |
| 点击 第1行第1列 | **（没有格子被选中）** | 第1行第1列 | ❌ |
| 按两次 → | 第1行第2列 | **（没有格子拿到焦点）** | ❌ |

### 14.2 根因（两个问题，第二个更严重）

| # | 问题 | 根因 |
| --- | --- | --- |
| 1 | **点格子根本没选中**（选中框不出现） | 隐藏的 EditText 铺满整格，触摸被它吃掉，单元格自己的 click 事件从未触发；它反而因为 `focusableInTouchMode` 自己拿到了焦点 |
| 2 | **方向键只动边框不动焦点** | `ShiciGrid.select()` 只改视觉（`setCellSelected`），从来没把输入焦点搬到新格 → 光标与输入法都留在旧格，**接着用输入法打的字会落进上一格** |

### 14.3 修法

| 位置 | 改动 |
| --- | --- |
| `widget\GridCellView.kt` | 新增 `onInterceptTouchEvent() = true`：触摸一律由格子自己接管，点击事件必然触发；新增 `focusForTyping(showIme)`：把焦点（连同光标）显式移到本格，`showIme` 只决定要不要唤起输入法 |
| `widget\ShiciGrid.kt` | `select()` 改为**任何情况下都把焦点跟到选中格**（原来只在 `focus=true` 时才请求输入法，移动时什么都不做）；`focusNextEmpty()` 改为只转移焦点、不重复唤起输入法 |
| 光标外观 | 隐藏输入框改为 `gravity=center` + 朱砂色 2dp 光标（新增 `cursor_fhl_vermilion.xml`），光标落在选中格正中、与红框同色，一眼看出"字会打进哪一格" |

## 二十、第九轮：修"二次检索把输入框清空"（2026-10-15）

### 20.1 根因与修法

`ChengyuFragment.onSecondSearch()` 里原本有一段"清空输入与错误提示"的代码，把 4 个输入格擦干净了
（当时的设计意图是"空出表格让你填新条件"）。但实际用法是**先筛出一批结果、再补一格继续缩小范围**，

| `onClearCurrent()` | 同样清空输入框 | **不动输入框**（退回上一层只是换结果，不动用户填的条件） |
| 层级配色标注 | 退回上一层时用 `emptySet()` 重绘 → **绿色标注丢失** | 新增 `levelHits` 与 `levels` 平行记录每层的命中位次，退回上一层时**恢复原有的绿色标注** |

## 二十一、第十轮：二次检索改成"当场执行"（2026-10-16）

> 用户澄清期望：**"检索完成后，用户往输入框输入了新内容后，点击二次检索，程序在上一次的检索结果中进行检索并给出新的结果。"**
> 也就是说——**二次检索自己就该是那个"执行"动作**，而不是先进入"待筛状态"、再让用户按一次「检索」。

### 21.1 改法

| 模块 | 原来 | 现在 |
| --- | --- | --- |
| 成语 | 点「二次检索」= 清空输入框 + 进入待筛状态（还要再按一次「检索」才出结果） | 点「二次检索」→ **当场用当前 4 格内容，在上一次的结果里再筛一次并给出新结果**；输入框全程保留 |
| 名士 | 点「二次检索」= 进入待筛状态 + 滚回顶部（还要再按一次「检索」） | 点「二次检索」→ **当场把"还没用上的新条件"叠加到上一次结果上并给出新结果**；若还没挑新条件，则提示"请先选择或输入新的条件，再点「二次检索」"并滚回条件区 |
| 提示条 | `二次检索中 · 当前范围：N 条`（表示"待筛状态"） | `在上一次 N 条结果中筛出`（表示"这一批是从上一次的 N 条里筛出来的"） |
| 层级入栈 | 无论有没有命中都入栈（**没命中会把候选范围清空，之后怎么改条件都搜不出来**） | 只在**有命中**时入栈；没命中只提示，候选范围保持在上一次结果，改条件即可继续搜 |
| 代码重复 | `doSearch` 与 `onSecondSearch` 各写一套 | 抽成 `validatedCells()` + `runSearch()`（成语）、`applyPending()`（名士）两个入口共用 |

`narrowing` 这个"待筛标记"随之删掉——它还暴露了一个老问题：**`levels.lastOrNull()` 与 `levels.last()` 在非空时完全等价**，
所以那个标记对"检索"的行为其实没有任何影响，属于无效状态。

### 21.2 验证（新增/更新回归脚本）

## 二十二、第十一轮：成语也做"检索键自动收起"，并把规则统一成一条（2026-10-16）

> 用户要求：**"成语或者名士的检索首次开始后，原先的检索键自动隐藏；恢复初始状态时恢复。"**

第十轮把两个检索入口合并之后，**"检索"和"二次检索"做的事情已经完全一样了**（都是在当前这一层结果里筛），
所以首次检索出结果之后，"检索"键就是纯占地方——尤其在手机上，它挤掉的是结果区的高度。
这一轮把名士已有（但带条件判断）的行为统一成**一条规则**，并补到成语上。

### 22.1 统一后的规则

**检索键可见 ⟺ 当前没有可继续筛的结果层（`levels.isEmpty()`）**

| 时刻 | 检索键 | 上方三个键 |
| --- | --- | --- |
| 初始状态（还没检索） | **显示** | 隐藏（结果区是空态） |
| 选了条件、还没检索 | 显示 | 隐藏 |
| **首次检索出结果后** | **隐藏** | 清空所有 · 清空当前 · 二次检索 |
| 检索后有结果、又改了条件 | **隐藏**（不再"放回来"——改完直接点「二次检索」） | 三个键 |
| 检索没命中（0 条） | **显示**（见下） | 清空所有 · 清空当前（无"二次检索"） |
| 「清空所有」 | **显示** | 隐藏 |
| 「清空当前」退到最后一层之下 | **显示** | 隐藏 |
| 「清空当前」还有上一层 | 隐藏 | 三个键 |

### 22.2 相比第六轮（十六节）改了什么

| 项 | 第六轮（仅名士） | 现在（成语 + 名士） |
| --- | --- | --- |
| 覆盖模块 | 只有名士 | **成语 + 名士**（成语此前一直是常驻） |
| 判断依据 | `levels.isEmpty() \|\| pendingDirty`——**改了条件就把键放回来** | 只看 `levels.isEmpty()`，`pendingDirty` 整个删掉 |
| 改了条件之后 | 检索键回来（暗示"要按检索"），可它与「二次检索」已经完全等价，属于误导 | 保持收起，条件挑完直接点「二次检索」 |
| 0 条命中时 | 名士：`levels` 为空 → 显示（行为对，但没人说明为什么） | 两个模块都**显式保证**：没命中不入层 → 键保持显示，用户不会因为"键藏起来了"而无法重搜 |

> 关键点：`levels` 只在**有命中**时才入栈（第十轮的改动），所以"没命中"天然等于"仍然处于初始层"，
> 检索键就会一直可用——这条巧合般的性质现在写进了注释与脚本，成了明确的行为约定。
