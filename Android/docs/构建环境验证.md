```kotlin
import java.util.Properties

// ⚠️ AGP 9.0+ 内置 Kotlin：绝对不要在这里加 id("org.jetbrains.kotlin.android")，
// 否则报 "The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0."
plugins {
    id("com.android.application")
}

// release 签名：从 keystore.properties 读取；文件不存在则 release 产物不签名（但依然能编译出 apk）。
val keystorePropsFile = rootProject.file("keystore.properties")
val keystoreProps = Properties().apply {
    if (keystorePropsFile.exists()) keystorePropsFile.inputStream().use { load(it) }
}
val releaseStoreFile = keystoreProps.getProperty("storeFile")?.let { rootProject.file(it) }
val hasReleaseKeystore = releaseStoreFile?.exists() == true

android {
    namespace = "com.fhlsearch.spike"

    // 本机只装了 platforms/android-37.0（Android 17），所以 compileSdk = 37
    compileSdk = 37

    defaultConfig {
        applicationId = "com.fhlsearch.spike"
        minSdk = 29          // Android 10
        targetSdk = 37
        versionCode = 1
        versionName = "1.0"
    }

    if (hasReleaseKeystore) {
        signingConfigs {
            create("release") {
                storeFile = releaseStoreFile
                storePassword = keystoreProps.getProperty("storePassword")
                keyAlias = keystoreProps.getProperty("keyAlias")
                keyPassword = keystoreProps.getProperty("keyPassword")
            }
        }
    }

    buildTypes {
        debug {
            isMinifyEnabled = false
        }
        release {
            isMinifyEnabled = false
            isShrinkResources = false
            proguardFiles(
                getDefaultProguardFile("proguard-android-optimize.txt"),
                "proguard-rules.pro",
            )
            if (hasReleaseKeystore) {
                signingConfig = signingConfigs.getByName("release")
            }
        }
    }

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }

    buildFeatures {
        viewBinding = true
    }
}

// 注意：内置 Kotlin 下不需要再写 kotlin { compilerOptions { jvmTarget = ... } }，
// 它的默认值就等于 android.compileOptions.targetCompatibility（这里 = 17）。
dependencies {
    implementation("androidx.core:core-ktx:1.19.1")
    implementation("androidx.appcompat:appcompat:1.8.0")
}
```

## 二、✅ 从零到 apk 的完整命令序列（PowerShell 可直接粘贴）

### 2.1 日常构建（脚手架已存在，最常用）

```powershell
$Sdk  = "C:\Users\<你的用户名>\AppData\Local\Android\Sdk"
$Proj = "_spike\android-min"
$Adb  = "$Sdk\platform-tools\adb.exe"

# ---- debug apk ----
cd $Proj
.\gradlew.bat :app:assembleDebug
# 产物：$Proj\app\build\outputs\apk\debug\app-debug.apk

# ---- release apk（自动用 keystore.properties 里的签名）----
.\gradlew.bat :app:assembleRelease
# 产物：$Proj\app\build\outputs\apk\release\app-release.apk

# ---- 验证签名 ----
cmd /c "`"$Sdk\build-tools\36.0.0\apksigner.bat`" verify --print-certs `"$Proj\app\build\outputs\apk\release\app-release.apk`""

# ---- 装到设备/模拟器并拉起 ----
& $Adb install -r "$Proj\app\build\outputs\apk\debug\app-debug.apk"
& $Adb shell am start -n com.fhlsearch.spike/.MainActivity

# ---- 截图（注意：PowerShell 的 > 会破坏二进制，必须 screencap 到设备再 pull）----
& $Adb shell screencap -p /sdcard/shot.png
& $Adb pull /sdcard/shot.png "$Proj\docs\emulator-shot.png"
```

### 2.2 全新机器从绝对零开始（没有 JDK21、没有 wrapper、没有 cmdline-tools 时）

```powershell
# ---------- 0. 目录 ----------
$Sdk  = "C:\Users\<你的用户名>\AppData\Local\Android\Sdk"
$Spike = "_spike"
New-Item -ItemType Directory -Force -Path "$Spike\dl" | Out-Null

# ---------- 1. 下载免安装 JDK 21（可选；本机 JDK 25 已实测可用，只是给 CI/保险起见）----------
Invoke-WebRequest -Uri "https://aka.ms/download-jdk/microsoft-jdk-21-windows-x64.zip" `
  -OutFile "$Spike\dl\jdk21.zip" -UseBasicParsing
tar -xf "$Spike\dl\jdk21.zip" -C $Spike
Rename-Item "$Spike\jdk-21.0.12.1+1" "jdk21"      # 版本号按实际下载到的改
& "$Spike\jdk21\bin\java.exe" -version

# ---------- 2. 下载 Gradle 发行包（仅用于生成 wrapper，只需一次）----------
Invoke-WebRequest -Uri "https://services.gradle.org/distributions/gradle-9.8.1-bin.zip" `
  -OutFile "$Spike\dl\gradle-9.8.1-bin.zip" -UseBasicParsing
tar -xf "$Spike\dl\gradle-9.8.1-bin.zip" -C "$Spike\gradle-dist"

# ---------- 3. 生成 wrapper ----------
#    ⚠️ 必须在空目录里生成，否则会把 AGP 下载提前算进"首次构建"耗时
$gen = "$Spike\wrapper-gen"
New-Item -ItemType Directory -Force -Path $gen | Out-Null
Set-Content "$gen\settings.gradle.kts" 'rootProject.name = "wrapper-gen"' -Encoding UTF8
cmd /c "`"$Spike\gradle-dist\gradle-9.8.1\bin\gradle.bat`" -p `"$gen`" wrapper --gradle-version 9.8.1 --distribution-type bin --no-validate-url --network-timeout 60000 --retries 10 --no-daemon"
Copy-Item "$gen\gradlew","$gen\gradlew.bat" "$Spike\android-min\" -Force
New-Item -ItemType Directory -Force -Path "$Spike\android-min\gradle\wrapper" | Out-Null
Copy-Item "$gen\gradle\wrapper\*" "$Spike\android-min\gradle\wrapper\" -Force

# ---------- 4. 构建 ----------
cd "$Spike\android-min"
.\gradlew.bat :app:assembleDebug

# ---------- 5. （可选）cmdline-tools：本机原本没有，已装到 latest ----------
Invoke-WebRequest -Uri "https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip" `
  -OutFile "$Spike\dl\cmdline-tools.zip" -UseBasicParsing
tar -xf "$Spike\dl\cmdline-tools.zip" -C "$Spike\clt-tmp"
Copy-Item -Recurse -Force "$Spike\clt-tmp\cmdline-tools\*" "$Sdk\cmdline-tools\latest"
```

### 2.3 生成 release keystore（本次实际使用的命令）

```powershell
New-Item -ItemType Directory -Force -Path "_spike\android-min\keystore" | Out-Null
& "_spike\jdk21\bin\keytool.exe" -genkeypair -v `
  -keystore "_spike\android-min\keystore\fhlsearch-release.jks" `
  -alias fhlsearch `
  -keyalg RSA -keysize 2048 -validity 10000 `
  -storetype PKCS12 `
  -storepass fhlsearch2026 -keypass fhlsearch2026 `
  -dname "CN=fhlSearch Spike, OU=Dev, O=fhlSearch, L=Beijing, ST=Beijing, C=CN"
```
> 口令 `fhlsearch2026`，别名 `fhlsearch`，有效期 10000 天。
> ⚠️ 这是**预研用的测试 key**。正式交付用户手机前请重新生成正式 keystore 并离线备份——**APK 一旦用它签名发布，后续升级必须用同一个 key**，丢了就无法覆盖安装。

### 3.4 Gradle 的 Kotlin 版本是被 AGP 钉死的


## 四、⚠️ 踩过的坑与失败组合（含报错原文关键行）

### 坑 1（最坑）：`services.gradle.org` 从 JVM 访问不稳定 → wrapper 任务失败

**现象**：用 Gradle 生成 wrapper 直接失败：
```
> Task :wrapper FAILED
* What went wrong:
Execution failed for task ':wrapper' (registered by plugin 'org.gradle.wrapper').
> Test of distribution url https://services.gradle.org/distributions/gradle-9.8.1-bin.zip failed.
  Please check the values set with --gradle-distribution-url and --gradle-version.
Caused by: java.net.SocketTimeoutException: Connect timed out
Caused by: java.lang.RuntimeException: HEAD request to
  https://services.gradle.org/distributions/gradle-9.8.1-bin.zip failed:
  response code (-1), timeout (10000ms)
```

**根因（用自写 NetTest.java 实测对比）**：`services.gradle.org` **只有它**不稳，其余仓库都很快很稳：

| 地址 | JVM HEAD | JVM GET |
|---|---|---|
| `services.gradle.org/distributions/...` | 有时 200（2301ms），有时超时 | **超时失败** |
| `dl.google.com/dl/android/maven2/...` | 200 (190ms) | 200 (130ms) |
| `repo.maven.apache.org/...` | 200 (825ms) | 200 (279ms) |
| `plugins.gradle.org/m2/` | 200 (878ms) | 200 (197ms) |

- Gradle wrapper 任务对 distribution URL 做了一次 **HEAD 校验，超时只有 10 秒**，撞上抖动就失败。
- 系统里配了代理 `127.0.0.1:<端口>`（Clash 类），但 `ProxyEnable=0` **未启用**，WinHTTP 是直连，所以不是代理问题；`-Djava.net.preferIPv4Stack=true` 也**没帮上忙**（反而两次都失败）。
- 旁证：`C:\Users\<你的用户名>\.gradle\wrapper\dists\gradle-9.6.0-bin\...\gradle-9.6.0-bin.zip.part` 只有 884736 字节 —— 正是以前某次同样卡死留下的残骸。**别被它误导**。

**解决办法（已写进 gradle-wrapper.properties，这是本方案能稳的关键）**：
```properties
networkTimeout=60000
retries=10
retryBackOffMs=500
validateDistributionUrl=false
```
生成 wrapper 时带上 `--no-validate-url --network-timeout 60000 --retries 10`。
实测效果：`gradlew.bat --version` 时**第 1 次尝试失败**（`Connection timed out: getsockopt`），**第 2 次重试成功**下载完 151MB。没有 `retries=10` 这次预研就走不下去了。

**备用镜像**（若官方源持续抽风，把 `distributionUrl` 换掉即可）：
- `https://mirrors.cloud.tencent.com/gradle/gradle-9.8.1-bin.zip` ← HEAD 仅 **93ms**（比官方 2294ms 快 25 倍），GET 实测可下载
- `https://downloads.gradle.org/distributions/gradle-9.8.1-bin.zip` ← 官方 CDN 直连，也可用（HEAD 2294ms）
- ~~`https://mirrors.aliyun.com/gradle/...`~~ → 404，不可用

### 坑 2（AGP 9 最大行为变更）：`org.jetbrains.kotlin.android` 插件变成**致命错误**

**报错原文关键行**：
```
Caused by: org.gradle.api.InvalidUserCodeException: Failed to apply plugin 'org.jetbrains.kotlin.android'
The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0.
Solution: Remove the 'org.jetbrains.kotlin.android' plugin from this project's build file: app\build.gradle.kts.
See https://kotl.in/gradle/agp-built-in-kotlin for more details.
```

**原因**：AGP 9.0 起默认启用 **built-in Kotlin**，Kotlin 编译已内建。

**解决**：
1. 根 `build.gradle.kts` 和 `app/build.gradle.kts` 里**都删掉** `org.jetbrains.kotlin.android`，也**不要**再写 `org.jetbrains.kotlin:kotlin-gradle-plugin` 版本（原来我写的 `2.4.21` 是多余且有害的）。
2. 删掉 `kotlin { compilerOptions { jvmTarget = ... } }` —— 官方明确：jvmTarget **默认就等于** `android.compileOptions.targetCompatibility`，不用自己设。
3. 若原来用 `android.kotlinOptions{}`，要迁移到 `kotlin.compilerOptions{}`。
4. 若用 kapt，要换成 KSP 或 `com.android.legacy-kapt`。

> 顺便：这条错误信息很有欺骗性——它出现在"编译 Kotlin"的表象下，但其实是**配置阶段**就挂了（4 秒就退出，堆栈全是 Gradle 内部帧）。别去查 Kotlin 版本兼容性，直接删插件即可。
>
> ⚠️ 另有一条我**没有采用**的退路：`android.builtInKotlin=false` + `android.newDsl=false` 可以退回旧方式继续用 kotlin 插件，但官方说 **AGP 10 将强制内置 Kotlin**，所以不建议。

### 坑 3：`sdkmanager.bat` / `avdmanager.bat` 拒绝 JDK 25

**报错原文**：
```
Java version 17 or higher is required.
To override this check set SKIP_JDK_VERSION_CHECK
```
JDK 25 明明 ≥ 17，是它版本号解析的老 bug。

**两种解法（均已验证可用）**：
```powershell
# 解法 A：把 JAVA_HOME 指到 JDK 21
cmd /c "set JAVA_HOME=_spike\jdk21&& `"$Sdk\cmdline-tools\latest\bin\avdmanager.bat`" list avd"
# 解法 B：跳过版本检查
cmd /c "set SKIP_JDK_VERSION_CHECK=1&& `"$Sdk\cmdline-tools\latest\bin\avdmanager.bat`" list avd"
```
> 本次因为 AVD 已存在、`emulator.exe -list-avds` 也能用，所以**没有真正依赖 avdmanager 建 AVD**，但仍把 `cmdline-tools` 装好了备用。

### 坑 4：`adb exec-out screencap -p > shot.png` 在 PowerShell 里会写出坏图

PowerShell 的 `>` 是文本重定向，会把 PNG 二进制写坏。**必须**：
```powershell
& $Adb shell screencap -p /sdcard/shot.png
& $Adb pull /sdcard/shot.png .\shot.png
```

### 坑 5（无害，但会骗到脚本）：JDK 25 下 `apksigner.bat` 往 stderr 吐警告

```
WARNING: A restricted method in java.lang.System has been called
WARNING: java.lang.System::loadLibrary has been called by org.conscrypt.NativeLibraryUtil ...
WARNING: Use --enable-native-access=ALL-UNNAMED to avoid a warning ...
```
PowerShell 会把 stderr 当 `NativeCommandError`，看起来像命令失败（甚至标成 `[exit code: 1]`），但**签名验证其实是成功的**（会正常打印 `Verifies` 和证书 DN）。
→ 用 `cmd /c "...apksigner.bat..."` 包一层就干净了。

### 坑 6：中文资源与编码

`gradle.properties` 里必须有 **`-Dfile.encoding=UTF-8`**（已加进 `org.gradle.jvmargs`），否则 aapt2 处理中文 `strings.xml` 可能报 `Invalid unicode`。所有 `.xml`/`.kt` 必须存成 **UTF-8（无 BOM）**。

## 六、📌 一句话总结：将来给 fhlSearch 做完整构建，推荐哪套配置

> **用「工作区免安装 JDK 21（或本机 JDK 25）+ Gradle 9.8.1 wrapper + AGP 9.4.1 + AGP 内置 Kotlin 2.2.10，compileSdk/targetSdk = 37、minSdk = 29、build-tools 36.0.0」，并且一定要在 `gradle-wrapper.properties` 里写上 `retries=10 / networkTimeout=60000 / validateDistributionUrl=false`（本机访问 `services.gradle.org` 不稳，这是唯一真正的环境坑），构建脚本里绝不要出现 `org.jetbrains.kotlin.android` 插件。**

理由速览：
1. AGP **9.4.1 是唯一正式支持 API 37 的稳定版**（AGP 8.x 上限 36），正好匹配本机只有 `android-37.0` 的现实。
2. JDK 25 和 JDK 21 **都实测可用**，不必折腾 JDK；但 CI 上建议固定 JDK 21 更省心。
3. AGP 9 内置 Kotlin 让构建脚本**更简单**，但**Kotlin 版本被锁在 2.2.10**，这是要接受的前提。
4. 冷启动约 3 分钟（853MB 依赖），之后增量构建 **8 秒**、无改动 **3 秒**；release 首次 45 秒。日常开发体感完全没问题。
